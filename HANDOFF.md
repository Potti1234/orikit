## 2. Product goal

OriKit is an independent MIT-licensed experiment inspired by Foldkit. It
tests whether a Foldkit-compatible Elm architecture can share application
behavior across:

- Foldkit on the web.
- NativeScript with real controls on Android.
- NativeScript with real controls on iOS later.
- Narrow Kotlin and Swift escape hatches where platform code is valuable.

The core loop is:

```text
event
  -> typed Message
  -> synchronous pure update(Model, Message)
  -> new Model + serializable Commands
  -> supervised interpreter
  -> typed completion Message
```

The desired product and visual character is documented in
[`PRODUCT.md`](PRODUCT.md): calm, precise, native, and Apple-inspired without
forcing identical pixels across platforms.

OriKit is not affiliated with Foldkit, NativeScript, Apple, Google,
JetBrains, or their maintainers.

## 4. Non-negotiable architectural invariants

- `update` is synchronous, deterministic, exhaustive, and effect-free.
- Model, Message, Command, history, and replay data contain no DOM nodes,
  native objects, callbacks, promises, or mutable SDK handles.
- Every external result returns through the dispatch queue as a typed Message.
- UI handlers dispatch Messages; they never mutate the Model.
- NativeScript renders and hosts platform integration. It does not own domain
  state.
- Web and native targets use the same canonical logical transition fixtures.
- Replay never executes Commands or acquires resources.
- Platform behavior belongs behind typed capabilities or explicit
  `.android.ts` and `.ios.ts` files.
- Kotlin and Swift boundaries must remain narrow and strongly typed.
- Do not add React, Vue, Angular, or another state framework.
- Do not start KMP or a TypeScript-to-Kotlin compiler without a new accepted
  ADR.
- Do not introduce a general portable view AST during the current phases.
- Do not claim iOS verification without macOS and Xcode evidence.

### Authorize the phone

1. Enable Developer options and USB debugging.
2. Connect the phone by data-capable USB cable.
3. Unlock the phone.
4. Accept the new laptop's “Allow USB debugging?” RSA prompt.
5. Prefer “Always allow from this computer.”
6. Confirm:

   ```powershell
   adb devices -l
   ```

   It must show `device`, not `unauthorized` or `offline`.

If the prompt does not appear:

```powershell
adb kill-server
adb start-server
adb devices -l
```

If it still does not appear, use the phone's Developer options to revoke USB
debugging authorizations, reconnect, and accept the new key.

## 11. Known limitations and caveats

### In-memory storage

Todo persistence is currently in memory. Relaunching starts with the fixture
Todo. Durable storage is not implemented.

### Separate web and native runtimes

- Web remains a genuine Foldkit application using Foldkit Runtime and
  Commands.
- NativeScript uses `@orikit/runtime`.
- Shared Programs, Stories, and canonical traces prove semantic parity.
- Do not replace Foldkit Runtime on web merely to maximize code sharing.

### Cancellation

`RuntimeAbortSignal` is structural and portable. It is not nominally the DOM
`AbortSignal`. Platform adapters may be required for APIs that insist on a
native/browser signal object.

Native SDKs may ignore cancellation. Session/branch/command identity and
completion quarantine are still mandatory.

### Runtime branches

Low-level branch replacement exists to prove stale completion quarantine. The
historical selection, warning, resume, and remote inspector experience remains
Phase 7.

### iOS

No iOS build, simulator, JavaScriptCore, Swift, VoiceOver, or physical-device
verification has run. Do not say that iOS works yet.

### Repository-wide lint

The Phase 4 implementation files pass targeted Biome checks.

`pnpm lint` currently also scans unrelated `branding/` and `site/` files and
reports accessibility diagnostics including:

- Missing SVG titles in `branding/logo/*.svg`.
- An invalid `href="#"` and decorative SVG diagnostic in `site/index.html`.

These files were not part of OriKit Phase 4 and were deliberately
preserved. Do not “fix” or delete them without first establishing their owner
and scope.

Targeted Phase 4 check:

```powershell
pnpm biome check packages/runtime packages/todo/src/application.ts packages/todo/src/program.test.ts apps/mobile-spike/app/todo/todo-page.ts tools/phase3/verify-todo-android.ps1 tools/phase4 tools/verify-portable-imports.mts package.json
```

### Web build warning

The Vite production build passes but warns that `node:assert`, imported by an
Effect testing module, was externalized for browser compatibility. It has not
caused a runtime or Scene failure. Investigate it in a focused dependency
cleanup; do not hide it blindly.
